# 验收与限制

更新：2026-10-28。预发布版本 `0.3.0rc9` 在独立测试环境 QA12 基础上增加停止路径修复、运行诊断、安装检查和 Agentloop 排版调整。仅部署专用测试实例，没有切换生产。

## 可复现的离线验证

`python3 scripts/verify.py` 运行 174 项核心、Transport、Runtime、Hermes 生命周期、会话、统计与呈现测试，阻断 socket 外连，另外检查合成突发/持续快照的终稿一致性。测试使用临时数据库和固定 fixture，无需真实机器人、凭据或本机研究缓存。

Hermes 的两个原生方法以带来源 hash 的 MIT 测试样本分发。普通源码验证不声称已检查安装在用户机器上的 Hermes。可选固定宿主检查见 [安装说明](installation.md)；固定验收目标为 Hermes 0.22.1，SDK 1.7.5。

HTML 预览包含 10 个场景、48 帧；既有布局检查覆盖 320/390/768/1440 四种宽度共 192 帧。预览是合成事件回放，不能代替真实 Feishu 客户端。

- 话题附件实际下载后内容核对。

- 正常任务触发的 Markdown 列表空行投影修正，避免正文完整却误降级为文本。

2026-10-28 新增验证：

## 停止时延仍需区分的边界

已复现并修复：同群另一个慢命令持有原生 chat lock 时，`/stop` 排队等待。新路径直接进入原生 `handle_message`，保留权限、来源和会话判定；离线回归与真实宿主 smoke 均覆盖此场景。

本轮实网样本从适配器记录入站到原生 run generation 失效约 3.63 秒；进入停止处理后到失效约 37 毫秒，处理返回还包含发送命令回执的等待。测试实例在首次样本出现约 37.5 秒、复测时超过 100 秒的事件循环采样间隔异常，具体根因尚未确定。因此不能把这次修复描述为稳定的秒级端到端停止，也不能把历史长等待全部归因于同一把锁。

`health.json` 保存有界阶段耗时、事件循环间隔和当前运行事实，便于后续区分入站、宿主调度与卡片提交问题。它不包含提示词、正文或身份标识，也不替代最终卡片回读。

## 性能与统计的真实含义

合成测试测量本地合并、终稿一致性和 Python 分配，不代表飞书吞吐、模型性能或网络 p95。没有同负载对照数据支持“比其他插件更快”。

输出均速 = 本轮已回报输出 Token / 精确已用时长，包含思考与工具等待，不是模型解码速率。估时至少需要 5 个满足当前进度的可比成功样本，冷启动显示积累进度；不会随发布附送真实历史数据。

## 尚未完成或不支持

- 移动端、其他单聊/群类型、长期压力与延迟分布。
- 飞书服务端真实限流、全链路网络中断、整个网关崩溃及其交叉组合；本轮覆盖的是独立投递进程和受控 Transport 故障。
- 停止与终稿投递的稳定延迟分布；测试宿主调度异常的独立根因尚未确定。
- 长任务的原生 `Working` 气泡与卡片底栏的统一收尾。本轮一次超过三分钟的任务已完成，但原生提示仍留在卡片外；该提示目前沿用宿主路径，不能视作仍在执行。
- 真实审批全链路、委派 Agent 用量完整归属，以及超过两个并发执行的验收。
- 多 profile 共进程、多进程共享库、分布式运行、plugin host 子进程隔离。
- 旧 fork 的压缩/重试提示合并、自定义 clarify 卡片和普通消息自动 FIFO/redirect 策略迁移。

原生审批/消息路径保留不等于该交互已完整实网验收。超过卡片预算后的文本分段保留全文，但不能承诺各段都有卡片信息栏。有限节点预算保护展开性能，不等于全历史浏览器。
